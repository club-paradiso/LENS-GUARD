# LENS-GUARD 개발 결과

2026년 10월 27일 기준으로 Demo와 PCAP 분석을 실행할 수 있는 로컬 프로토타입을 구현했습니다. 실제 카메라 데이터는 수집하지 않았으며 실제 카메라 탐지 정확도는 검증하지 않았습니다.

## 구현한 기능

- Python 엔진: 패킷 길이, 시간, 송신 주소, 가능한 경우 RSSI를 분석합니다. 통신 내용을 복호화하거나 표시하지 않습니다.
- 실험용 분류기: 전송 지속성, 큰 패킷 비율, 전송량, 변동성으로 0–100점을 계산합니다. 70점 이상을 검토 후보로 표시합니다. 카메라일 확률이 아닙니다.
- React 대시보드: 기기별 근거, 시간 그래프, 후보 목록, 파일 분석, JSON 보고서 내보내기를 지원합니다.
- Demo: Run simulation으로 1초 간격의 분석 갱신을 확인할 수 있습니다. 합성 데이터이며 무선 수집은 실행하지 않습니다.
- PCAP/PCAPNG: Ethernet, 802.11, Radiotap을 지원합니다. 승인된 송신 MAC 주소를 지정해야 합니다. 파일 출처는 사용자 진술이며 프로그램이 실측 여부를 인증하지 않습니다.
- 개인정보 최소화: 원본 파일을 서버에 저장하지 않고 결과에는 분석마다 달라지는 주소 가명을 사용합니다. 분석 필터가 과도한 수집을 사후에 정당화하지는 않습니다.

## 실행

저장소 폴더에서 다음 명령을 실행한 뒤 http://127.0.0.1:8765 를 엽니다.

```sh
./scripts/start.sh
```

설치와 빌드를 마쳤다면 다음 명령으로 시작할 수 있습니다.

```sh
.venv/bin/python -m lens_guard serve
```

첫 설치에는 인터넷이 필요합니다. 실행 중 외부 분석 API나 유료 서비스를 사용하지 않습니다. GitHub Actions는 수동 실행 방식으로 준비했으며 실행하지 않았습니다.

## 검증 결과

| 검사 | 결과 |
|---|---|
| `python -m pytest -q` | 36개 통과, 외부 라이브러리 경고 1개 |
| `npm run build` | TypeScript 검사와 배포용 빌드 통과 |
| `npm run test:e2e` | 브라우저 테스트 5개 통과 |
| 합성 시나리오 평가 | 8개 유형 × 12개 시드 = 96건 |

합성 평가에서는 정확도 62.5%, 정밀도 50.0%, 재현율 66.7%, 오탐률 40.0%를 기록했습니다. 정탐 24건, 오탐 24건, 정상 분류 36건, 미탐 12건입니다. 영상통화와 백업을 후보로 잡았고 저전송률 카메라를 놓쳤습니다. 센서와 유휴 상태는 판단 보류 또는 관측 없음으로 남기되, 이진 평가에서는 비후보로 집계했습니다. 이 수치를 실제 카메라 탐지 성능으로 해석하면 안 됩니다.

앱 내 브라우저 호출은 시간 초과로 끝나 Playwright Chromium으로 검증했습니다. 데스크톱 1505×1045, 모바일 390×844 화면에서 파일 분석, 출처 표시, 후보 선택, 재생, 보고서 다운로드를 확인했습니다. 모바일 그래프 축이 너무 작게 보이던 문제를 수정했습니다. 디자인 시안과 구현 화면의 레이아웃·색상·글꼴·표·반응형 배치를 비교했고 출처와 가명 표시 등 의도적으로 바꾼 부분은 검증 기록에 남겼습니다.

## 연구 조사

SCamF는 논문과 Android 구현 설명을 확인했지만 이번 조사에서 저자가 공개한 코드 저장소를 확인하지 못했습니다. 공개 코드가 없다고 단정하지는 않습니다.

Lumos는 논문 링크가 가리키는 실제 GitHub 저장소를 내려받아 확인했습니다. 현재 공개 구현에는 Raspberry Pi·USB Wi-Fi·iOS 구성이 필요하고 별도 Unity 파일도 요구합니다. 작업 중인 다른 Python 프로세스를 종료하는 코드가 있어 실행하지 않았습니다.

CamLoPA도 공개 코드를 확인했지만 Raspberry Pi·Nexmon CSI와 추가 인터페이스를 요구합니다. 이번 프로젝트는 이 연구들의 완전한 재현물이 아닙니다. 자세한 근거와 확인한 커밋은 [연구 조사](RESEARCH.md)에 기록했습니다.

## 남은 기능과 한계

현재 Mac은 macOS 15.6.1, arm64 환경입니다. Wi-Fi 인터페이스와 Wireless Diagnostics 설치는 확인했지만 패킷 접근 권한이 거부돼 모니터 모드의 실제 수집 성공 여부는 확인하지 못했습니다. 실시간 무선 수집, 채널 이동, 위치 추정, CSI, 학습 기반 분류기는 구현하지 않았습니다.

후보는 카메라 확정 판정이나 불법성 판단이 아닙니다. 후보가 없더라도 안전을 보장하지 않습니다. 다음 검증에는 소유·승인 범위가 명확한 장비와 독립적으로 확인한 정답 데이터가 필요합니다.

## 2단계: 방향 특징, 평가 재설계, 소유 기기 실측 경로

2026년 10월 27일에 진행했습니다. 실제 카메라 데이터와 라벨링된 실측 데이터는 여전히 0건입니다. 아래 수치는 모두 합성 생성기 기준 동작이며 실제 탐지 성능이 아닙니다.

### 바뀐 점

- **방향 판정:** 802.11은 송신자(TA)와 수신자(RA) 주소로, Ethernet은 송신·수신 MAC으로 각 프레임의 송신(tx)·수신(rx)을 구분합니다. 중계 주소(addr3)는 이중 집계를 막으려고 세지 않습니다.
- **rules-0.2:** 업링크 비율, 100ms 단위 버스트 자기상관으로 구한 주기와 주기성 점수, 버스트 간격 변동계수, 패킷 크기 구성, 지속 형태를 점수로 합칩니다. 70점이 아니라 55점 이상을 검토 후보로 봅니다. 방향 정보가 없으면 업링크 특징을 0으로 채우지 않고 `insufficient_direction`으로 판단을 보류합니다.
- **rules-0.1 비교:** 기존 규칙을 그대로 다시 계산해 함께 보여 줍니다. 1단계 평가 96건의 점수가 모두 그대로 재현되는지 테스트로 확인합니다.
- **평가 설계:** 1단계 생성기는 영상통화와 카메라를 같은 코드로 만들어 둘을 원리적으로 구분할 수 없었습니다. 이번에는 프로필마다 파라미터를 따로 두고, 근거가 있는 값과 가정을 구분해 기록했습니다. 개발용 180건으로만 임계값을 정했고, 그 규칙과 예측을 [사전등록](PREREGISTRATION.md)해 커밋한 뒤 잠금 테스트 270건과 분포 이동 270건을 처음 실행했습니다. 테스트 결과를 본 뒤에는 규칙을 바꾸지 않았습니다.
- **소유 기기 실측 경로:** `lens-guard evaluate-labeled --manifest`와 사용자가 직접 sudo로 실행하는 `scripts/capture-own-host.sh`를 추가했습니다. 스크립트는 개발 중에 실행하지 않았습니다. 절차는 [소유 기기 실측 절차](OWNED_DEVICE_PROTOCOL.ko.md)에 정리했습니다.
- **대시보드:** 기기 상세에서 특징별 점수 기여, 방향 정보 가용성, 보류 사유, rules-0.1·0.2 비교를 볼 수 있습니다. 연구 화면에는 합성 평가 표와 출처 배너를 추가했습니다.
- **CI:** push와 pull request에서도 실행됩니다. 저장소가 비공개라 계정의 GitHub Actions 사용 시간을 씁니다. 첫 실행은 GitHub 계정의 결제 실패 또는 지출 한도 문제로 작업이 시작되지 않았습니다. CI 검증은 통과가 아니라 막힘 상태입니다.

잠금 테스트에서는 영상통화와 백업 오탐이 30건씩에서 0건으로 줄었습니다. 남은 오탐 30건은 모두 라이브 방송 송출입니다. 라이브 방송은 카메라와 같은 방식으로 인코딩된 영상이라 이 메타데이터만으로는 구분하지 못합니다.

분포 이동 세트에서는 성능이 크게 떨어졌습니다. 발표자 모드 영상통화 29/30건과 1초 간격 센서 18/30건이 후보가 됐고, 움직임이 큰 카메라 3건을 놓쳤습니다. 공통 원인은 점수 구조입니다. 업링크 우세·지속 존재·연속 형태만으로 50점이 되는데 임계값은 55점이어서, 꾸준한 업로드에 약한 주기성만 더해져도 후보가 됩니다. 사전등록한 예측 가운데 "긴 GOP 카메라 미탐"과 "속도 제한 백업 오탐"은 틀렸습니다. 자세한 분석은 [평가 설계와 결과](EXPERIMENTS.md)에 있습니다.

### 검증

| 검사 | 결과 |
|---|---|
| `python -m pytest -q` (Python 3.14) | 74개 통과 |
| `python -m pytest -q` (Python 3.11, CI와 같은 버전) | 74개 통과 |
| `python -m lens_guard evaluate` | 720건, 커밋한 결과와 동일 |
| `npm ci`, `npm run build`, `npm run test:e2e` | 빌드 통과, 브라우저 테스트 5개 통과 |

작업 초기에 `python -m lens_guard`가 "No module named lens_guard"로 실패했습니다. macOS가 가상환경의 `.pth` 파일에 숨김 속성을 붙였고 Python 3.13 이상은 숨김 `.pth`를 건너뛰기 때문입니다. 대처 방법은 [개발 안내](DEVELOPMENT.md)에 적었습니다.

### 남은 한계

- 실데이터 미검증: 라벨 평가 경로는 합성 매니페스트로만 시험했습니다.
- Mac 한 대로는 영상통화·백업·웹 탐색·유휴 같은 비카메라 라벨만 만들 수 있습니다. 카메라 라벨에는 본인 소유 IP 카메라와 별도 수집 경로가 필요합니다.
- 업링크 비율 구간, GOP 범위, 영상통화 파라미터는 논문에 수치가 없어 가정으로 정했습니다.
- 후보는 여전히 확정 판정이 아니며, 후보가 없다는 결과가 안전을 보장하지 않습니다.
