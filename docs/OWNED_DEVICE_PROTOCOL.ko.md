# 소유 기기 실측 절차

이 문서는 본인 소유 기기의 트래픽을 직접 수집해 라벨을 붙이고, LENS-GUARD 규칙을 평가하는 절차입니다. **LENS-GUARD는 수집을 자동으로 시작하지 않습니다.** 수집은 사용자가 터미널에서 직접 실행합니다. 2026년 10월 27일 현재 이 절차로 수집한 실데이터는 없으며, 평가 경로는 합성 매니페스트로만 시험했습니다(실데이터 미검증).

## 1. 범위와 금지 사항

- 본인 소유 기기, 또는 소유자에게 명시적으로 허락받은 기기만 대상으로 합니다.
- 민원실, 사무실, 카페, 숙소 등 제3자 네트워크에서는 수집하지 않습니다. 장소 관리자의 허락이 있어도 그 자리에 있는 다른 사람의 기기까지 허락된 것은 아닙니다.
- 주변 채널 전체를 수집하는 방식(Wireless Diagnostics의 Sniffer 등)은 이 절차에서 사용하지 않습니다. 분석 단계에서 허용 목록으로 걸러도 과도한 수집이 정당화되지는 않습니다.
- 통신 내용의 복호화, 인증 우회, 다른 기기에 대한 프로빙은 하지 않습니다.
- 수집 파일과 실제 MAC 주소는 GitHub에 올리지 않습니다.

## 2. 추가 장비 없이 만들 수 있는 라벨

본인 Mac 한 대로는 **오탐을 일으키는 비카메라 클래스**만 만들 수 있습니다. 각 수집 중에는 해당 행동 하나만 하고, 다른 앱의 동기화와 업데이트는 가능한 한 멈춥니다.

| 라벨 | 수집 방법 | 권장 길이 |
|---|---|---|
| `video_call` | 상대방 동의를 받은 1:1 영상통화. 발표자 모드(내 화면만 송출)는 별도 수집으로 남기고 `notes`에 적습니다. | 2–5분 |
| `cloud_backup` | 본인 계정의 클라우드 저장소에 큰 파일 업로드 | 업로드가 끝날 때까지, 최대 10분 |
| `web_browsing` | 일반 웹 탐색 | 2–5분 |
| `media_streaming` | 동영상 시청 | 2–5분 |
| `live_stream_upload` | 본인 계정으로 비공개 라이브 방송 | 2–5분 |
| `idle` | 앱을 모두 닫고 대기 | 5분 |

이 라벨들은 규칙이 비카메라를 후보로 잘못 표시하는지 확인할 때 씁니다. 합성 평가의 분포 이동 세트에서 발표자 모드 영상통화와 라이브 방송은 후보로 표시됐습니다. 실제 기기에서도 같은지 확인하는 것이 첫 번째 목표입니다.

## 3. 카메라 클래스의 한계

카메라 라벨(`camera_stream`, `camera_low_rate`, `camera_motion`, `camera_other`)은 **본인 소유 IP 카메라가 있어야** 만들 수 있습니다. 카메라 트래픽은 Mac을 거치지 않으므로, 이 스크립트로 Mac 자신의 트래픽을 수집해서는 카메라 라벨을 만들 수 없습니다. 스크립트는 카메라 라벨을 받지 않습니다.

카메라를 수집하려면 다음 중 하나가 필요합니다. 두 방법 모두 이 저장소의 스크립트 범위 밖이며, 아직 검증하지 않았습니다.

- 본인 소유 공유기나 스위치의 포트 미러링으로 카메라 MAC만 걸러 수집
- 본인 소유 네트워크에서 모니터 모드로 카메라 MAC만 걸러 수집([macOS 수집 경계](MACOS.md) 참고). 이 Mac의 모니터 모드 수집은 권한 문제로 확인하지 못했습니다.

## 4. 수집 전 확인

1. 저장소가 iCloud Drive 등 동기화 폴더 안에 있는지 확인합니다. 그렇다면 `captures/`도 클라우드로 올라갈 수 있으므로, 동기화하지 않는 위치에 저장소를 두거나 수집 직후 파일을 옮깁니다.
2. Wi-Fi 인터페이스 이름과 현재 MAC 주소를 확인합니다.

   ```sh
   networksetup -listallhardwareports
   ifconfig en0 | awk '/ether /{print $2}'
   ```

   macOS의 비공개 Wi-Fi 주소 기능을 켜 두면 네트워크마다 주소가 달라집니다. 스크립트는 수집 시점의 인터페이스 주소와 `--mac` 값이 같은지 확인합니다.
3. 먼저 sudo 없이 확인 실행(dry run)을 합니다. 아무것도 수집하지 않고 필터와 저장 경로만 출력합니다.

   ```sh
   scripts/capture-own-host.sh --iface en0 --mac <위에서 확인한 주소> --label video_call --seconds 180
   ```

## 5. 수집

```sh
sudo scripts/capture-own-host.sh --run --iface en0 --mac <주소> --label video_call --seconds 180 --packets 100000
```

- `CAPTURE`를 직접 입력해야 수집이 시작됩니다.
- BPF 필터는 `ether host <주소>`입니다. 이 Mac이 보내거나 받는 프레임만 남습니다.
- 각 프레임에서 14바이트(Ethernet 헤더)만 저장합니다. IP 주소와 통신 내용은 파일에 남지 않습니다. 원래 프레임 길이는 기록됩니다.
- 최대 600초, 200,000프레임에서 멈춥니다. 파일은 Git이 무시하는 `captures/`에 권한 600으로 저장됩니다.
- 수집 시작·종료 시각과 실제로 한 행동을 바로 적어 둡니다.

Mac 자신의 트래픽은 Ethernet 형식으로 기록되므로 보고서의 가시성은 `ethernet_src_dst`입니다. 공중의 무선 프레임을 관측한 것이 아닙니다.

## 6. 매니페스트 작성과 분석

[예시 매니페스트](examples/labeled-manifest.example.json)를 `captures/manifest.json`으로 복사해 수정합니다. 파일 경로는 매니페스트 기준 상대 경로이며 같은 폴더 밖을 가리킬 수 없습니다.

| 필드 | 내용 |
|---|---|
| `collector_statement` | 소유 또는 허락 범위 진술(20자 이상) |
| `file` | 수집 파일 이름 |
| `devices` | `mac`과 `label` 쌍. 유니캐스트 주소만 받습니다. |
| `method` | `own_host_tcpdump`, `owned_ap_port_mirror`, `owned_network_monitor_mode`, `other_declared` |
| `authority` | `owned` 또는 `explicit_permission` |
| `authorization_statement` | 이 수집에 대한 진술 |
| `captured_at` | UTC 오프셋이 있는 ISO 8601 시각, 예: `2026-11-01T20:15:00+09:00` |

```sh
.venv/bin/python -m lens_guard evaluate-labeled --manifest captures/manifest.json --output captures/labeled-report.json
```

결과의 출처는 항상 `user_declared_authorized_capture`이고 `authenticity`는 `not_verified_by_program`입니다. 프로그램은 라벨, 소유 여부, 수집 방법의 형식만 확인하며 사실 여부는 인증하지 않습니다. 결과에는 파일 경로와 MAC 주소가 들어가지 않고, 기기는 분석마다 바뀌는 가명으로 표시됩니다.

## 7. 해석

- 비카메라 라벨만 있으면 정밀도와 재현율은 계산되지 않고 오탐률만 의미가 있습니다.
- 수집 몇 건으로 일반적인 탐지 성능을 말할 수 없습니다. 기기와 세션 단위로 결과를 보고합니다.
- 결과를 보고 규칙을 고치면, 그 데이터는 이후 평가에 다시 쓰지 않습니다. 새 규칙은 [사전등록](PREREGISTRATION.md)처럼 먼저 기록한 뒤 새 수집으로 평가합니다.

## 8. 보존과 삭제

1. 분석이 끝나면 원본 수집 파일을 지웁니다. 보존이 필요하면 7일을 넘기지 않는 것을 권장합니다.

   ```sh
   rm captures/<파일 이름>.pcap
   ```

2. 오래 남길 것은 가명 처리된 결과 JSON과 라벨 메모뿐입니다. 결과 JSON에도 실제 MAC 주소를 적지 않습니다.
3. `git status`로 `captures/` 안의 파일이 커밋 대상에 없는지 확인합니다.
4. 영상통화 상대방이 삭제를 요청하면 해당 파일과 결과를 바로 지웁니다.
